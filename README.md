# audio_cpp_dart

Dart bindings for [audio.cpp](https://github.com/0xShug0/audio.cpp): in-process
TTS, ASR, VAD, diarization, source separation, voice conversion, music
generation and more, on ggml.

- **Native FFI**: `@Native` external functions generated by
  [`package:ffigen`](https://pub.dev/packages/ffigen) from the official C ABI
  (`include/audiocpp.h`), bound to a code asset.
- **Build hooks**: [`package:hooks`](https://pub.dev/packages/hooks) +
  [`package:code_assets`](https://pub.dev/packages/code_assets) provide the
  native library automatically for `dart run`, `dart test`, `dart build cli`
  and every Flutter platform. Nothing to install by hand.
- **Platforms**: Android, iOS, macOS, Windows, Linux.

| Target | Library comes from | Default backend |
| --- | --- | --- |
| Linux x64 | upstream release (sha256-verified) | `cpu` |
| Windows x64 | upstream release (sha256-verified) | `cpu` |
| macOS arm64 / x64 | upstream release (sha256-verified) | `metal` / `cpu` |
| Android (arm64, armv7, x64) | CMake build with the NDK Flutter provides | `cpu` |
| iOS device / simulator | CMake build with Xcode | `metal` |
| Linux arm64, Windows arm64 | CMake build on the host | `cpu` |

The bindings track audio.cpp **v0.9.3** (C ABI 0.2).

## Usage

```dart
import 'package:audio_cpp_dart/audio_cpp_dart.dart';

Future<void> main() async {
  final registry = Registry();
  final model = await registry.loadModelAsync(
    'models/Kokoro-82M-GGUF/kokoro-82m-q8_0.gguf',
    family: 'kokoro_tts',
  );
  final session = await model.createSessionAsync('tts', backend: Backend.best);  // or Backend.cpu

  final request = Request(text: 'Hello from Dart.', language: 'en-us')
    ..setOption('voice-id', 'af_heart');
  final result = await session.runAsync(request);
  Wav.write('hello.wav', result.audio!);

  for (final h in <Closeable>[request, session, model, registry]) {
    h.close();
  }
}
```

Speech recognition and VAD take audio instead:

```dart
final asr = await model.createSessionAsync('asr');
final result = await asr.runAsync(Request(audio: Wav.read('speech.wav')));
print(result.text);
for (final w in result.words) print('${w.word} ${w.startSample}');
```

Streaming sessions are pull-based, as in the C API:

```dart
final vad = model.createSession('vad', mode: SessionMode.streaming);
final chunk = vad.streamPolicy.preferredChunkSamples;
vad.startStream();
for (final block in blocksOf(audio, chunk)) {
  final event = vad.push(block);            // StreamEvent?
  for (final e in vad.drainEvents()) { /* partial text, voice activity */ }
}
final finalResult = vad.finishStream();
```

API overview:

- `Registry` – loader set; `families`, `loadModel` / `loadModelAsync`.
- `Model` – `family`, `description`, `supports(task, mode:)`, `languages`,
  `options(OptionScope)` (runtime discovery of `--load/--session/--request-option`),
  `createSession` / `createSessionAsync`.
- `Session` – `run` / `runAsync`, `prepare`, and streaming: `streamPolicy`,
  `startStream`, `push` / `pushAsync`, `nextEvent`, `drainEvents`,
  `finishStream` / `finishStreamAsync`, `resetStream`.
- `Request` – text, language, input audio, voice reference / voice id, style
  controls, options, list options, artifacts.
- `TaskResult` – audio, text, segments, speaker turns, words, named audio,
  artifacts. Plain Dart data, copied out of native memory.
- `AudioCppException` carries the `AudioCppStatus` and `audiocpp_last_error()`.
- `Wav` – minimal WAV reading/writing.

`*Async` methods run the blocking native call on a background isolate, so the
UI isolate stays responsive. A session handles one call at a time; overlapping
calls throw `StateError`. Handles are freed by `close()` or by a
`NativeFinalizer`; the C ABI keeps parents alive, so closing out of order is
safe.

Models are downloaded separately; see the
[audio.cpp model docs](https://github.com/0xShug0/audio.cpp#models). On mobile,
model files must be on the file system (copy them out of the asset bundle or
download them at runtime, see `example/flutter_app`).

## Configuring the native build

Configuration is read from the **root** package's `pubspec.yaml` (your app):

```yaml
hooks:
  user_defines:
    audio_cpp_dart:
      # auto (default): prebuilt where available, otherwise build from source
      # prebuilt | build | local
      source: auto
      # Linux/Windows prebuilt: cpu, cpu-portable, vulkan, vulkan-portable,
      #   cuda12.8 / cuda13.3 (Linux), cuda12.4 / cuda13.3 (Windows)
      # macOS: metal (arm64), cpu (x64). Source builds: cpu, metal, vulkan, cuda, hip
      backend: vulkan
      # Source builds only:
      model_set: full          # full | core | custom
      models: [kokoro_tts]     # with model_set: custom
      source_dir: ../audio.cpp # use a local checkout instead of downloading
      cmake_args: [-DGGML_CPU_ARM_ARCH=armv8.2-a+dotprod]
      build_type: Release
      jobs: 8
      # source: local – a library file, or a directory of libraries to bundle
      local_library: /opt/audiocpp/libs
      # Windows: bundle the MSVC runtime DLLs shipped with the release
      bundle_msvc_runtime: true
```

Notes:

- CUDA prebuilts also download and bundle the matching CUDA runtime archive
  (several hundred MB). The NVIDIA driver, and the Vulkan loader for Vulkan
  builds, must be installed on the machine.
- Source builds need CMake (Android: the SDK's CMake is found through
  `ANDROID_HOME`), plus Xcode for Apple targets and Visual Studio for Windows.
  The first build compiles audio.cpp and takes a while; the result is cached
  by the hook. `model_set: core` (framework models only, e.g. Silero VAD)
  builds much faster.
- Android builds use `c++_static`, no OpenMP, and 16 KB page alignment.
- Minimum OS versions come from audio.cpp: **macOS 13.3** and **iOS 16.3**
  (floating-point `std::to_chars`). Set your Flutter app's deployment target
  to at least that (`MACOSX_DEPLOYMENT_TARGET` / `IPHONEOS_DEPLOYMENT_TARGET`).
- GitHub's macOS runners expose a paravirtualized GPU on which ggml-metal
  aborts on some ops; use `Backend.cpu` there.

## Development

```sh
dart pub get
dart test                 # runs Silero VAD from test/fixtures on the real library
dart run tool/ffigen.dart # regenerate bindings (needs libclang)
```

CI (`.github/workflows/ci.yml`) runs the test-suite against the prebuilt
libraries on Linux, Windows and macOS (arm64 and x64), source builds on Linux
(x64, arm64), macOS and Windows, and Flutter integration tests on Linux,
Windows, macOS, an Android emulator and an iOS simulator.
